## 4. Inconsistencies: Repository vs. Slide Deck & Spec

1. **Re-Plan Stage Count Discrepancy (7 of 11 vs. 3 of 9)**:
   - **Slide Deck & Full Architecture**: Identifies 11 total pipeline stages (`intake`, `bureau_kyc`, `trust_gate`, `cashflow`, `fraud`, `risk`, `policy`, `structuring`, `cam`, `ledger`, `human`). When new evidence (electricity bills) arrives, 4 upstream stages are unaffected and reused (`intake`, `bureau_kyc`, `trust_gate`, `fraud`), while all 7 downstream stages are invalidated and must recompute (`cashflow`, `risk`, `policy`, `structuring`, `cam`, `ledger`, `human`).
   - **Frontend Repository**: Hardcoded to 9 stages total, claiming **3 recomputed** (`cashflow`, `risk`, `structuring`) and **6 cached** (`intake`, `bureau`, `trust_gate`, `fraud`, `cam`, `ledger`). This incorrectly assumed that `cam` and `ledger` would not need updating when the loan sizing changed from ₹45L to ₹66L.
   - **Resolution Required**: The redo count, reuse count, and compute saved percentage must **never** be hardcoded constants; they must be computed directly by running topological traversal on the NetworkX dependency graph.

2. **Case Identifiers & Nomenclature**:
   - Backend generator keys: `sharma_traders`, `clean_file`, `linked_firm_ring`, `honest_cash_shop`, `prompt_injection_pdf`.
   - Backend Case IDs: `case_sharma_traders`, `case_clean_apex_auto`, `case_linked_ring_sharma_verma_gupta`, `case_honest_cash_maa_laxmi_kirana`, `case_injection_nexus_cloud`.
   - Slide deck labels: Slide 2 refers to "Sharma Traders", "Maa Laxmi Kirana", and "Apex Auto", but Slide 8 labels the circular ring entities as "Sharma Traders -> Verma Textiles -> Gupta Logistics".
   - The IDs and counterparty names must be standardized across backend schemas, synthetic generators, and frontend views.

3. **Missing Test Coverage vs. Acceptance Criteria**:
   - Current test suite only covers Phase 1 synthetic scenario dictionary integrity (13 tests).
   - Missing:
     - Policy engine limit rejection test (`bank_a.yaml` and `bank_b.yaml`).
     - Pure loan sizing and DSCR unit tests.
     - Honest cash-heavy non-fraud classification test under real stage execution.
     - Orchestrator parallel wave timing vs sequential execution test.
     - Incremental re-planning hash immutability test.
     - Multi-variant adversarial prompt injection tests.
     - Zero-disbursal route scanner test.

## 5. Architectural Remediation Plan (Stage 1 Scope)

To transition Verifin from a prototype scaffold with static mock data into a fully working, deterministic multi-agent system, Stage 1 will implement:

1. **`backend/app/stages/orchestrator.py`**:
   - Dynamic NetworkX DAG builder per case.
   - `waves()` method scheduling parallel execution via `asyncio.gather`.
   - Canonical JSON SHA-256 `input_hash(case)` computation for every stage.
   - Topological descendant invalidation marking nodes `STALE` while retaining `CACHED` nodes.
   - Deterministic alphabetical stage result merging.
   - Token and execution time budget checks.
   - Event emitter yielding typed events (`plan_built`, `wave_started`, `stage_started`, `stage_finished`, `stage_skipped`, `stage_reused`, `replan`, `case_done`).

2. **`backend/app/stages/` (Individual Stage Modules)**:
   - `intake.py`: Multi-document ingestion, unstructured PDF parsing, strict untrusted text delimitation.
   - `bureau_kyc.py`: Independent credit bureau score and KYC tradeline verification.
   - `trust_gate.py`: Pure Python triangulation grading numbers into A, B, C with human-readable rationale.
   - `cashflow.py`: Verified monthly cash computation and utility bill adjustment.
   - `fraud.py`: NetworkX directed cycle detector (circular rings), linked entity premise matching, and outside-world turnover dissipation test.
   - `risk.py`: Deterministic DSCR calculation.
   - `policy.py`: YAML policy pack loader (`bank_a.yaml`, `bank_b.yaml`) enforcing hard caps and rejecting breaching term sheets.
   - `structuring.py`: Pure Present Value loan sizer `PV(r, n, pmt)` and dynamic Evidence Ladder generator.
   - `cam.py`: Credit Assessment Memorandum generator with automated citation verification.
   - `ledger.py`: Mock ledger state machine holding transactions as `PENDING_APPROVAL`.

3. **`backend/app/api/` (FastAPI Server & Routes)**:
   - `main.py` with CORS, security headers, and exception handlers.
   - `GET /cases` and `GET /cases/{id}`.
   - `GET /cases/{id}/events` via Server-Sent Events (SSE) streaming real-time orchestrator execution events.
   - `POST /cases/{id}/evidence` triggering real incremental re-plans.
   - `POST /cases/{id}/replay` verifying bit-for-bit replay hash reproducibility.
   - `POST /cases/{id}/decision` accepting authenticated officer actions (`SANCTIONED`, `SENT_BACK`, `ESCALATED`).

4. **`tests/` Expansion**:
   - `test_orchestrator.py`: Proves parallel waves run faster than sequential; proves incremental re-planning only reruns stale nodes; proves counts are derived directly from the graph.
   - `test_policy_engine.py`: Proves a breaching term sheet is rejected in code.
   - `test_sizing_calculators.py`: Proves Sharma computes ₹45L initially and ₹66.5L after evidence using pure math.
   - `test_zero_disbursal.py`: Inspects the FastAPI route table and ledger state machine, asserting zero money release endpoints exist.
   - `test_adversarial_injection.py`: Verifies defense against prompt injection variants across varied phrasings, table cells, and document metadata.
